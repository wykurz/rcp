# copy a directory tree
$$ rcp ./dataset ./dataset-copy \
    --progress --summary
# or send it to another host
$$ rcp ./dataset host:/data/dataset \
    --auto-deploy-rcpd --progress
# remove an old scratch directory
$$ rrm ./scratch/old-run \
    --progress --summary
# recursive removal, with progress
# and a summary when the work is done
# set a tree's group and permissions
$$ rchm --group data \
    --mode "f:g+rw d:g+rwxs" \
    ./dataset --progress --summary
# separate rules for files and directories

01 / THE ESSENTIALS

The work you do every day.

Three fundamental operations, with tools built to handle large directory trees.

rcp

↗

Copy. Here or across hosts.

Copy files and directory trees locally or between Linux hosts. Preserve metadata, track progress, and tune concurrency when you need to.

Copy examples →

rrm

−

Remove large directory trees.

Clear out scratch space, old datasets, and build output. Remove large filesets with progress reporting and a summary of the work.

Removal documentation →

rchm

±

Put permissions in order.

Change ownership, groups, and permissions recursively. Apply different rules to files and directories in the same operation.

Permissions guide →
02 / MEASURED PERFORMANCE

Less time waiting on a copy.

A million files is a useful place to start. In these shared-filesystem measurements, default rcp completes the copy in minutes.

From the performance report. $files files × 1 MB ($total_bytes), copied within each filesystem. Mean command wall time; lower is faster. These are two workloads from the report, not a general speedup claim. Filesystems use different hardware; the charts compare tools within each setting.
